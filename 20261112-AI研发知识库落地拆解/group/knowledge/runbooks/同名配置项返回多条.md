# 适用场景

一个组件读取配置时，返回了多条同名配置项，且条件不一致；前端表现为「条件时对时不对」。

# 首查入口

记下**组件名**和**重复项名**，直接对照两张配置表里同一组件的定义。不要从渲染层或缓存开始。

# 核心判断

- 同一组件的配置可能同时存在新旧两套，服务端分别映射，没有按组件覆盖去重。
- 条件不一致来自两条持久化的表达式；渲染层看到的只是合并后的结果。
- 前端卡片重复、缓存脏数据都只是现象，不是原因。

# 修复约束

- 先定权威配置是哪一套，再清理遗留那套；只改其中一处没有用。
- 清理后确认所有读取入口都指向同一套，不能只修当前页面用到的那条路径。

# 验证

- 同一组件按名称查询只返回一条。
- 修改条件后，所有使用该组件的页面表现一致。
- 用「条件时对时不对」这类描述，做一次全新会话的命中验证。
