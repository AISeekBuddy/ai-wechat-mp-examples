# 工作组知识

只写 `group/knowledge/`（含 `index/`），不碰草稿正文，也不碰公共包；本组负责人担保。

## 流程一 · 判断怎么进这一层

1. **提案**：读草稿 `draft.md` 与本组 `catalog.md`，按「适用场景 / 首查入口 / 核心判断 / 修复约束 / 验证」五段写出完整预览和目标路径。收判断，不收过程。
2. **确认**：整份提案给人看，明确确认后才动手；前期一律人工确认，不自动晋升。
3. **写入**：落到对应分类，`index/documents.json` 加一行（标题、摘要、关键词、路径、更新时间），草稿状态改为已处理。只有本组成立的内容留这里；剥离项目仍认得出来的走公共包。

## 流程二 · 运行时这一层怎么被用

1. 先读当前任务、需求、规格和相关代码，确定这次改什么。
2. 扫 `knowledge/index/documents.json`，挑一两篇；索引只放标题、摘要、关键词、路径、更新时间，负责「找到」。
3. 读命中条目正文，先看**首查入口**把第一步定死；引用时说明适用范围，并与当前代码、测试对照。
4. 对不上就是这条过期：就地改本组条目并同步索引，不退回草稿。彻底不成立才标作废，且必须指向替代条目。
5. 不默认读 `drafts/`、`pending/`、`source-log.md`。

正式条目不出现会话路径、草稿路径、本机路径。
