# 定义

配置项以「主体标识 + 配置项名」为唯一键；同一个键只允许一个权威来源生效。

# 关系与结构

配置可以有多份存储：历史版本、迁移中间态、多环境副本。但读取链路必须先在单一权威源上完成覆盖去重，再把结果交给下游。下游只读去重后的结果，不参与合并。

# 适用范围

任何「同一标识存在多份定义、下游按条件选用」的配置体系。

# 边界

- 不涉及具体存储实现、表名和字段名。
- 不涉及单次问题的排查过程与修复记录。
- 未过评审前不进正式分类、不进 `index/documents.json`、不参与默认检索。

# 与团队条目的关系

同一条判断：团队层的《同名配置项返回多条的排查手册》写「这次先看什么」，本条写「为什么所有组都该这么设计」。前者本组担保，本条待跨组评审担保。
